## 2. 功能概述

### 2.1 功能背景

V3.0版本的漏洞管理功能存在以下限制：
1. **数据来源单一**：漏洞数据仅来源于一键扫描，由LLM分析软件清单得出
2. **被动发现**：用户无法主动关注特定CVE漏洞
3. **缺乏灵活性**：对于新披露的高危漏洞，用户无法提前纳入管理

在实际运维场景中，存在以下需求：
- 安全团队需要关注特定的高危CVE（如新披露的0day漏洞）
- 这些CVE可能尚未在扫描中发现，但需要提前关注和验证
- 用户希望通过LLM查询CVE详情并统一管理
- 用户需要对自定义CVE进行多主机的POC验证或修复

### 2.2 功能目标

1. **CVE查询入库**：用户输入CVE编号，调用LLM查询详情并入库管理
2. **状态固化**：同一时间只允许一个CVE查询任务进行，防止并发冲突
3. **统一管理**：自定义CVE与扫描发现的CVE在漏洞列表中统一展示
4. **多主机操作**：支持选择多个主机进行POC验证或修复脚本生成
5. **独立状态追踪**：每个主机的脚本生成和执行状态独立显示

### 2.3 核心价值

| 价值点 | 描述 |
|:---|:---|
| **主动安全管理** | 用户可主动关注特定CVE，不必等待扫描发现 |
| **精准验证修复** | 支持多主机独立脚本生成，针对不同OS生成适配脚本 |
| **状态可视透明** | 每个主机的任务状态实时展示，便于运维追踪 |

### 4.3 交互规则

#### 4.3.1 CVE查询互斥规则

**规则描述**: 同一时间只允许一个CVE查询任务进行

**实现方式**:
1. 后端数据库约束：`custom_cve_queries`表中只能存在一条`status='querying'`的记录
2. 前端状态检查：打开对话框时检查是否有进行中的查询
3. 按钮状态控制：有查询进行中时禁用"查询CVE"按钮

**异常处理**:
- 用户尝试在查询进行中时提交新查询 → 显示提示，告知当前正在查询的CVE编号
- 查询超时（超过60秒） → 自动标记为失败，释放锁定

#### 4.3.2 主机选择规则

| CVE来源 | 可选择的主机 | 说明 |
|:---|:---|:---|
| 扫描发现 (source='llm_analysis') | 仅受影响主机 | 从`host_vulnerabilities`表获取关联的主机 |
| 自定义查询 (source='custom_query') | 全部主机 | 从`hosts`表获取所有在线主机 |

#### 4.3.3 脚本生成规则

1. **异步生成**: 每个主机的脚本独立异步生成，不阻塞其他主机
2. **OS适配**: 根据主机的`os_type`字段生成适配的脚本
3. **超时控制**: 单个脚本生成超时时间为30秒
4. **并发限制**: 同时最多生成5个脚本，超出部分进入队列

#### 4.3.4 批量执行规则

1. **仅执行已生成**: 只执行状态为"已生成"的主机脚本
2. **跳过未完成**: 状态为"生成中"、"未生成"、"失败"的主机自动跳过
3. **确认提示**: 执行前显示将执行和跳过的主机列表
4. **任务创建**: 创建一个任务组，包含多个单主机任务

### 4.4 数据校验规则

#### 4.4.1 CVE编号格式校验

**正则表达式**: `^CVE-\d{4}-\d{4,}$`

**校验时机**: 前端输入时实时校验 + 后端接收时再次校验

**示例**:
- ✅ `CVE-2021-44228`
- ✅ `CVE-2023-12345`
- ❌ `CVE-21-44228` (年份不完整)
- ❌ `CVE-2021-123` (编号不足4位)
- ❌ `2021-44228` (缺少CVE前缀)

#### 4.4.2 CVE重复校验

**校验逻辑**: 调用查询API前，先检查`vulnerabilities`表中是否已存在该CVE编号

**重复处理**:
- 如果已存在 → 提示"CVE已存在于数据库中"，不允许重复查询
- 如果不存在 → 允许查询

---

### 4.5 异常处理

#### 4.5.1 查询失败场景

| 失败原因 | 错误提示 | 处理方式 |
|:---|:---|:---|
| CVE不存在 | "未查询到该CVE信息" | 提供重试按钮 |
| LLM超时 | "LLM服务响应超时，请稍后重试" | 提供重试按钮 |
| LLM配额用尽 | "LLM额度已用完，请联系管理员" | 不提供重试，需管理员处理 |
| 网络错误 | "网络连接失败，请检查网络" | 提供重试按钮 |
| 输入格式错误 | "CVE编号格式不正确" | 前端校验，不发送请求 |

#### 4.5.2 脚本生成失败场景

| 失败原因 | 错误提示 | 处理方式 |
|:---|:---|:---|
| LLM生成失败 | "脚本生成失败: {详细错误}" | 显示错误详情，提供重试 |
| 超时 | "脚本生成超时（超过30秒）" | 提供重试按钮 |
| 主机离线 | "主机已离线，无法生成脚本" | 不提供重试，需主机上线 |
| OS不支持 | "不支持的操作系统: {os_type}" | 不提供重试 |

#### 4.5.3 执行失败场景

| 失败原因 | 错误提示 | 处理方式 |
|:---|:---|:---|
| Agent离线 | "Agent已离线，无法执行" | 任务标记为失败，等待Agent上线后重新下发 |
| 脚本执行超时 | "脚本执行超时" | 任务标记为超时，可重新执行 |
| 脚本执行错误 | 返回stderr内容 | 显示错误日志，可重新执行 |

## 6. 验收标准

### 6.1 功能验收

| 功能点 | 验收标准 | 优先级 |
|:---|:---|:---|
| CVE输入验证 | 格式必须为`CVE-YYYY-NNNNN`，前后端双重校验 | P0 |
| 查询状态锁定 | 同一时间只允许一个CVE查询，重复请求返回友好提示 | P0 |
| 查询成功 | CVE信息正确入库，source='custom_query'，影响主机数=0 | P0 |
| 查询失败 | 显示明确错误原因，支持重试 | P0 |
| 主机选择 | 自定义CVE显示全部主机，扫描CVE只显示受影响主机 | P0 |
| 多主机脚本生成 | 每个主机独立生成脚本，显示各自的生成状态 | P0 |
| 任务状态列表 | 实时显示各主机的脚本生成状态（生成中/已生成/失败/未生成） | P0 |
| 批量执行 | 只执行已生成脚本的主机，跳过未完成的主机并提示 | P1 |
| 页面刷新恢复 | 页面刷新后能恢复查询中状态和脚本生成中状态 | P1 |

### 6.2 性能验收

| 指标 | 标准 |
|:---|:---|
| CVE查询响应时间 | < 30秒（LLM调用时间） |
| 单主机脚本生成时间 | < 20秒 |
| 多主机脚本生成 | 支持并发生成，每个主机独立超时控制 |
| 状态轮询间隔 | 2秒/次 |
| 列表加载时间 | < 1秒 |

### 6.3 兼容性验收

| 环境 | 要求 |
|:---|:---|
| 浏览器 | Chrome 90+, Firefox 88+, Safari 14+ |
| 操作系统 | 前端支持跨平台，后端脚本支持 CentOS/Ubuntu/RHEL |
| 数据库 | PostgreSQL 12+ |
| API | RESTful，遵循现有API规范 |

## 7. 风险评估与缓解措施

| 风险 | 影响 | 缓解措施 |
|:---|:---|:---|
| LLM查询超时/失败 | 用户体验差 | 设置合理超时（30秒），提供重试按钮 |
| 并发查询冲突 | 数据不一致 | 数据库级别唯一约束 + 应用层互斥锁 |
| 脚本生成失败 | 无法执行验证/修复 | 显示详细错误信息，支持重试 |
| 大量主机脚本生成 | 资源消耗大 | 并发控制（最多同时生成5个），队列机制 |

## 9. 附录

### 9.1 错误码定义

| 错误码 | 说明 |
|:---|:---|
| `CVE_QUERY_IN_PROGRESS` | 已有查询任务进行中 |
| `CVE_NOT_FOUND` | LLM未查询到该CVE信息 |
| `CVE_ALREADY_EXISTS` | 该CVE已存在于数据库中 |
| `CVE_INVALID_FORMAT` | CVE编号格式不正确 |
| `SCRIPT_GENERATION_FAILED` | 脚本生成失败 |
| `SCRIPT_NOT_GENERATED` | 脚本尚未生成，无法执行 |

### 9.2 状态流转图

```
CVE查询状态流转:
querying → success
         → failed

脚本生成状态流转:
pending → generating → generated
                       → failed
```
