# 弱密码应用资产 AI 约束与真实验证修复

## 问题描述

弱密码检测相关链路存在三个风险：

1. 应用资产分析没有强制要求 AI 只返回市面可识别的公开应用，可能把自研脚本、系统工具或临时进程识别为应用资产。
2. 同一主机上同类应用需要在资产与弱密码候选两个层面去重，避免重复展示和重复检测。
3. AI 生成弱密码字典在 LLM 不可用或失败时会退回本地规则生成，这会让“AI 生成”名义下保存非 AI 结果。

## 历史行为

历史弱密码资产分析 prompt 已要求只返回“市面已知的公开软件”且具备账号密码机制的应用。当前应用资产分析 prompt 没有同等约束；当前弱密码资产分析 prompt 有方向性约束，但返回覆盖要求不够硬。

## 修复设计

- 应用资产识别 prompt 明确要求：
  - 只返回公开发行、市场或开源社区可检索的应用。
  - 不返回自研业务进程、内部工具、自定义脚本、系统基础工具、语言运行时和监控/日志 Agent。
  - 返回 JSON 固定为 `{"applications":[...]}`，无可识别应用必须返回空数组。
- 服务端解析 AI 结果后再次过滤：
  - 归一化应用名称和分类。
  - 丢弃未知、自研、脚本、系统工具和低可信项。
  - 按同一主机内标准化应用类型去重，合并 PID、端口、配置路径和证据。
- 弱密码应用资产分析：
  - 对同一主机同一应用类型只保留一条资产，优先保留置信度更高、配置路径更多、最近采集的资产。
  - AI 返回必须覆盖全部输入应用类型，每个类型只能出现在 `needs` 或 `skip` 之一。
  - AI 返回键统一做应用类型归一化，缺失或未知类型视为 AI 返回不完整并重试。
- AI 生成弱密码字典：
  - 必须成功调用配置的 LLM。
  - LLM 不可用、调用失败、返回空列表或解析失败时返回错误，不保存本地规则生成结果。
  - 默认 1000 内置字典仍保留本地确定性生成，因为它不是“AI 生成”入口。

## 接口变化

无新增接口。`POST /api/v1/weak-password/dictionaries/ai-generate` 在 LLM 不可用或失败时从“保存本地生成字典”改为返回错误。

## 数据库变化

无表结构变化。现有 `host_application_assets(host_id, fingerprint)` 与 `weak_password_candidate_applications(host_id, application_type)` 约束继续使用。

## 安全影响

减少误把内部脚本和系统工具暴露为应用资产的风险；避免用户误信本地规则字典为 AI 生成结果。

## 兼容性影响

弱密码字典 AI 生成入口现在依赖可用 LLM 配置。未配置 LLM 的环境需要先配置模型后才能使用 AI 生成功能。

## 测试用例

1. 应用资产 AI 结果包含 Redis、Python 脚本、systemd 时，只保留 Redis。
2. 同一主机 Redis 多进程或多条资产只保留一条，合并 PID、端口、配置路径和证据。
3. 弱密码资产 AI 返回缺少某个输入应用类型时，服务端返回解析错误并重试。
4. 弱密码资产 AI 返回 `needs/skip` 覆盖全部输入时，候选只包含 `needs` 中的应用。
5. AI 字典生成使用 mock LLM 返回密码列表并保存为 `ai_generated`。
6. AI 字典生成在无 LLM 或 LLM 报错时返回错误，不保存字典。
7. 真实环境：构建并启动全栈，重装 Agent，安装或配置 Redis 弱口令，完成资产采集、弱密码资产分析、检测任务，至少产生一条弱密码命中。

## 回滚计划

如 LLM 输出约束导致候选过少，可仅回滚本次 prompt/解析过滤代码；数据库无需回滚。
