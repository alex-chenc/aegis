# 基线大模型修复触发语义修复设计

## 问题描述

基线任务当前混用了两类不同语义：

- 检测未通过：检测脚本正常执行完成，安全基线不合规。
- 任务执行失败：脚本语法、下发、超时、审计或运行环境错误，导致任务本身没有可靠完成。

旧说明中把 `CHECK + SUCCESS + exit_code=1` 也纳入 ReAct 自动修复闭环，导致“未通过”看起来自动进入修复基线。用户期望是：未通过就是未通过，不自动修复；只有检测/修复任务本身报错或失败时，才进入大模型修复并重新下发。

## 当前行为

1. 文档和前端仍使用“ReAct 修复/脚本修复”表述，和产品期望不一致。
2. 检测脚本提示词只要求 `0=通过、1=失败`，没有区分“合规未通过”和“执行错误”。
3. 修复脚本提示词只输入 `fix_content`，没有要求脚本必须满足检测逻辑的逆条件，容易出现“修复成功但复检仍未通过”。
4. 前端任务详情对“未通过”检测项提供直接“修复”入口，容易让用户误以为系统在检测后自动进入修复。

## 修复设计

1. 检测结果语义：
   - `CHECK` 脚本 exit code `0`：检测通过。
   - `CHECK` 脚本 exit code `1`：检测未通过，任务状态仍为 `SUCCESS`，不触发大模型修复。
   - `CHECK` 脚本 exit code `2+` 或 `<0`：检测任务执行失败，任务状态为 `FAILED`，允许进入大模型修复。
2. 修复任务语义：
   - `FIX` 脚本 exit code `0`：修复任务执行成功。
   - `FIX` 脚本 exit code 非 `0`：修复任务执行失败，允许进入大模型修复。
3. 大模型修复触发：
   - 只对 `FAILED` / `TIMEOUT` / `AUDIT_BLOCKED` 等执行异常开放。
   - `CHECK + SUCCESS + exit_code=1` 不触发，也不显示大模型修复入口。
4. 文案：
   - 前端所有“脚本修复/ReAct 修复”改为“大模型修复”。
5. 修复脚本生成：
   - Prompt 同时包含检测内容和修复建议。
   - 要求修复动作必须是检测逻辑的逆向满足条件。
   - 要求脚本修复后执行同等语义的验证，验证不通过时返回非 0。

## 组件变更

- `api-server/internal/llm/prompts.go`：增强检测/修复脚本生成提示词。
- `api-server/internal/service/script_generation_service.go`：生成修复脚本时传入检测内容和修复内容。
- `api-server/internal/service/self_healing_service.go`：大模型修复触发判断支持 CHECK 执行错误，但排除 CHECK 未通过。
- `server/internal/grpc_server/server.go`：Agent 结果映射时区分 CHECK 未通过与 CHECK 执行失败。
- `frontend/src/views/TaskDetail.vue`：更新状态文案和操作入口。
- 测试：补充后端单元测试覆盖结果语义和大模型修复触发条件。

## 接口与数据库

本次不变更 REST/gRPC 字段，不新增数据库列。继续使用 `status` 表示任务执行状态，使用 `exit_code` 表示检测业务结果。

## 安全影响

修复脚本 Prompt 增加“最小变更、备份、验证、不可破坏系统关键文件”等约束，并继续经过既有脚本审计。未通过检测项不再自动进入修复，降低误修复风险。

## 兼容性

旧检测脚本可能仍把执行异常返回 `1`，这类脚本无法被完美区分为“未通过”或“执行错误”。新生成的检测脚本会使用 `2+` 表示执行错误；历史脚本可通过重新生成脚本获得新语义。

## 回归测试用例

1. `CHECK + SUCCESS + exit_code=1` 展示为“未通过”，不展示“大模型修复”，不创建修复任务。
2. `CHECK + FAILED + exit_code=2` 展示为“检测失败”，展示“大模型修复”入口。
3. `FIX + FAILED + exit_code=1` 展示为“修复失败”，展示“大模型修复”入口。
4. `FIX + SUCCESS + exit_code=0` 展示为“修复成功”，不展示“大模型修复”入口。
5. 任务详情页面不再出现“脚本修复”“ReAct修复”文案，失败任务可保留补充修复建议入口。
6. 修复脚本生成 Prompt 同时包含检测内容、修复建议和“修复后验证必须通过检测等价条件”的约束。
7. Playwright 真实验证：登录 `admin/Admin@123`，进入基线任务详情，确认未通过检测项不自动进入修复，不显示旧文案。

## 回滚方案

如新语义影响已有脚本，可仅回滚 server 状态映射和前端入口；Prompt 增强兼容旧数据，不需要数据库回滚。
