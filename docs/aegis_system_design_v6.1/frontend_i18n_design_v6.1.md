# Aegis V6.1 前端中英文国际化设计

## 1. 问题与需求

Aegis 当前前端以简体中文为唯一界面语言，Element Plus 也在应用启动时固定使用 `zh-CN`。本次需求是在顶部“运维审计 / 智能体模式”模式切换控件旁新增中英文切换按钮，并使系统内可本地化的界面内容随语言实时变化。

本次设计目标如下：

- 支持 `zh-CN` 简体中文和 `en-US` 英文。
- 默认保持简体中文，兼容现有用户使用习惯。
- 语言切换无需刷新页面，不改变当前路由、筛选条件、表单状态、模式或智能助手会话。
- Element Plus 内置文案、业务界面文案、状态标签、日期数字、图表、提示和无障碍文本同步切换。
- 用户选择在刷新、退出登录和重新登录后继续生效。
- 新产生的系统通知、API 错误和智能助手输出具备按语言展示或生成的能力。
- 离线部署包内包含全部语言资源，不依赖外部翻译服务或 CDN。

代码中的当前模式名称为“运维审计 / 智能助手”。目标产品文案统一为：

| 中文 | 英文 |
|:---|:---|
| 运维审计 | Operations Audit |
| 智能体模式 | Agent Mode |

## 2. 范围与非目标

### 2.1 本次范围

- `frontend/` 应用框架、认证页面和全部业务模块的静态界面文案。
- Element Plus 的分页、日期选择器、空状态、弹窗等内置文案。
- 路由标题、面包屑、浏览器标题和导航菜单。
- 前端枚举、状态、风险级别、严重程度、相对时间、日期、数字和百分比格式化。
- REST 请求语言头及用户可见 API 错误的稳定错误码映射。
- 通知模板的语义化存储与前端翻译。
- 智能助手新运行的目标语言传递。
- 中英文资源完整性测试和中英文端到端回归。

### 2.2 非目标

以下内容属于业务数据或安全证据，不因切换界面语言而被自动改写：

- 用户输入、上传文档及已有智能助手历史消息。
- 主机名、IP、用户名、文件路径、命令、脚本、标准输出、错误输出和原始日志。
- Sigma 规则原文、漏洞原始描述、检测证据及外部系统返回内容。
- 已存储且没有语义模板键的历史通知。

系统可以在生成新内容时使用当前语言，但不对历史或任意业务文本做在线机器翻译，避免改变安全语义、审计证据和命令内容。

## 3. 当前行为

- `frontend/src/main.ts` 在注册 Element Plus 时固定注入 `zhCn`。
- `frontend/src/App.vue` 直接包含中文导航、模式选项、tooltip、面包屑首页和超时提示。
- `frontend/src/router/index.ts` 的 `meta.title` 保存中文展示文本，无法在运行时按语言解析。
- 页面、组件、store、API 拦截器和工具函数中存在分散的中文字符串及状态映射。
- 多个页面固定调用 `toLocaleString('zh-CN')`，部分页面直接调用不带语言参数的 `toLocaleString()`。
- API 拦截器优先展示服务端 `message` 或 `error` 字符串，缺少稳定的可翻译错误码。
- 通知表直接保存本地化后的 `title` 和 `content`，同一条通知不能在前端实时切换语言。
- 智能助手请求不携带界面语言；模型主要依据用户输入语言决定输出语言。
- 登录和首次设置管理员密码页面使用独立认证布局，当前没有主应用顶部工具栏。

初步静态盘点显示，`frontend/src` 下约有 101 个非测试生产文件包含中文字符，其中既包括用户可见文案，也包括注释和内部说明。实施时需要按用户可见性分类迁移，不能简单进行全文替换。

## 4. 目标行为

### 4.1 顶部语言按钮

主应用顶部右侧顺序调整为：

```text
[运维审计 | 智能体模式] [EN / 中文] [通知] [刷新] [用户]
```

- 中文模式下按钮显示 `EN`，点击切换到英文。
- 英文模式下按钮显示 `中文`，点击切换到中文。
- 按钮使用固定宽度，防止语言切换造成顶部布局跳动。
- 按钮提供当前语言对应的 tooltip 和 `aria-label`。
- 语言按钮紧邻模式切换控件，不改变模式切换的路由行为。
- 登录和首次设置密码页面右上角也复用同一语言组件，保证未登录用户能够选择语言。

### 4.2 切换行为

- 点击后立即更新当前页面，不刷新浏览器。
- 保留当前路由、路由参数、查询参数、表单和 store 状态。
- 同步更新 Vue 业务文案、Element Plus、图表、日期、数字和 `<html lang>`。
- 当前语言保存到浏览器本地存储。
- 多标签页通过 `storage` 事件同步语言；同步只更新展示，不触发业务请求或模式跳转。
- 正在执行的智能助手运行保持启动时的语言，下一次运行使用切换后的语言。

### 4.3 默认与回退

语言解析优先级：

```text
有效的本地持久化语言
  -> zh-CN 默认值
```

V6.1 不根据浏览器语言自动选择英文，避免升级后现有部署因浏览器设置产生不可预期的界面变化。读取到空值、非法值或不支持的语言时统一回退 `zh-CN`。

## 5. 总体设计

```text
LanguageSwitcher
  -> 全局 locale
     -> Vue I18n 业务文案
     -> Element Plus ConfigProvider
     -> 日期/数字/相对时间格式化
     -> ECharts 配置重新计算
     -> REST Accept-Language
     -> 智能助手运行 locale
     -> localStorage 与 html lang
```

设计原则：

- 全局只维护一个语言状态来源，组件、Pinia 和 Element Plus 不各自保存副本。
- store 和业务模型保存稳定枚举及原始数据，不保存翻译后的状态标签。
- 翻译发生在展示边界；API 参数、数据库枚举、工具名和协议字段保持英文稳定值。
- 两套资源随前端构建一起进入离线包，切换时不请求网络。
- 中文资源作为默认资源和最终兜底资源。

## 6. 前端组件设计

### 6.1 依赖与入口

引入适配当前 Vue 3 Composition API 的 `vue-i18n` 版本，并在安装时锁定具体版本。应用入口注册顺序：

```text
createApp
  -> Pinia
  -> Router
  -> Vue I18n
  -> Element Plus
  -> mount
```

`App.vue` 最外层使用动态 `el-config-provider`，同时覆盖主应用布局和认证布局：

```vue
<el-config-provider :locale="elementLocale">
  <router-view v-if="isAuthLayout" />
  <el-container v-else>...</el-container>
</el-config-provider>
```

`main.ts` 不再把 `zhCn` 作为不可变的全局配置；Element Plus 的语言由 Config Provider 响应式提供。

### 6.2 文件组织

```text
frontend/src/i18n/
├── index.ts
├── locale.ts
├── formatters.ts
└── locales/
    ├── zh-CN/
    │   ├── index.ts
    │   ├── common.ts
    │   ├── auth.ts
    │   ├── assets.ts
    │   ├── baseline.ts
    │   ├── vulnerability.ts
    │   ├── detection.ts
    │   ├── weakPassword.ts
    │   ├── settings.ts
    │   └── assistant.ts
    └── en-US/
        └── 与 zh-CN 相同结构

frontend/src/components/common/LanguageSwitcher.vue
```

两套语言资源按业务域拆分，避免单个大文件产生键名冲突。`zh-CN` 资源定义消息结构，`en-US` 必须满足相同的 TypeScript 结构或通过资源键完整性测试。

### 6.3 语言状态接口

支持的语言使用固定白名单：

```ts
type SupportedLocale = 'zh-CN' | 'en-US'
```

`locale.ts` 负责：

- 读取、校验和保存 `aegis_locale`。
- 更新 Vue I18n 全局 `locale`。
- 提供当前 Element Plus 语言包。
- 更新 `document.documentElement.lang`。
- 处理多标签页 `storage` 同步。
- 向非 Vue setup 上下文提供只读当前语言和全局翻译函数。

组件不得直接读写 `localStorage`，避免状态分叉。

### 6.4 翻译键命名

翻译键按“业务域.页面或组件.语义”命名，不使用中文原文作为键：

```text
common.actions.save
common.status.running
app.mode.operationsAudit
app.mode.agentMode
assets.applications.empty
weakPassword.tasks.deleteConfirm
assistant.approval.approve
```

带数量或变量的文案使用参数和复数规则，不在组件中拼接翻译片段：

```ts
t('tasks.exportSuccess', { count })
```

禁止以下实现：

- 根据翻译后的文本判断业务状态。
- 使用字符串替换把中文错误临时翻成英文。
- 在 store 中缓存翻译后的标签数组且不响应语言变化。
- 把命令、路径、标识符或用户数据传给通用翻译函数。

### 6.5 路由与面包屑

路由元数据由展示文本改成稳定键：

```ts
meta: { titleKey: 'routes.hosts' }
```

`App.vue` 的面包屑在计算时调用翻译函数。路由变化或语言变化时同步更新：

```text
页面标题 · Aegis
```

重定向、权限判断和路由名称不因国际化发生变化。

### 6.6 状态与枚举

API 和 store 继续保存原始值，例如：

```text
pending / running / completed / failed
critical / high / medium / low / info
read / write / execute
```

颜色、图标等视觉语义继续由原始值映射，标签通过翻译键映射。公共状态集中到 `common.ts`，业务特有状态保留在对应业务域资源中。

### 6.7 日期、数字和图表

`formatters.ts` 统一提供：

- 短日期、完整日期时间和仅时间格式。
- 相对时间，例如“刚刚 / Just now”“5 分钟前 / 5 minutes ago”。
- 整数、小数、百分比、字节和 token 数量格式。
- 无效时间的统一占位符。

清除生产代码中固定的 `toLocaleString('zh-CN')`。ECharts option 改为依赖当前语言的 `computed` 或在语言变化时调用 `setOption`，更新图例、坐标名、tooltip 和空状态，不重新请求业务数据。

## 7. API 与动态内容设计

### 7.1 REST 请求语言

Axios 请求拦截器为全部 REST 请求增加：

```http
Accept-Language: zh-CN
```

或：

```http
Accept-Language: en-US
```

服务端只接受支持列表中的标准值；缺失或非法时回退 `zh-CN`。语言不是权限信息，不参与认证、授权或审计主体判断。

### 7.2 API 错误契约

当前前端直接显示 `message`。目标响应在保持旧字段兼容的基础上增加稳定错误标识：

```json
{
  "code": 1001,
  "error_code": "TASK_DELETE_RUNNING",
  "params": {
    "count": 2
  },
  "message": "运行中的任务无法删除"
}
```

展示优先级：

```text
已知 error_code 的本地化文案
  -> HTTP 状态对应的本地化通用文案
  -> 本地化“请求失败”并附带可公开的请求标识
```

`message` 为旧客户端兼容字段，不再作为英文界面的首选展示内容。服务端内部错误、堆栈、SQL、命令参数和敏感信息不得直接透传给用户。

实施时先覆盖前端实际使用的 API handler，并建立错误码注册表，防止同一错误码表达不同语义。

### 7.3 通知内容

现有 `notifications.metadata` 为 JSONB，可在不新增数据库字段的情况下增加：

```json
{
  "i18n_key": "notifications.ruleAdjusted",
  "i18n_params": {
    "ruleTitle": "Suspicious Shell",
    "mitreId": "T1059.004",
    "version": "1.2"
  }
}
```

通知生产端仍写入中文 `title` 和 `content` 作为旧客户端和未知模板的兜底；新前端发现受支持的 `i18n_key` 时，根据当前语言即时渲染标题和正文。

兼容规则：

- 新通知应携带模板键和参数。
- 历史通知没有模板键时显示已存储原文。
- 业务参数保持原文，不翻译规则名、MITRE ID、主机名等内容。
- 未知模板键回退到通知原始标题和正文，不显示翻译键本身。

该方案复用现有 JSONB 扩展字段，不需要数据库 migration。

### 7.4 智能助手语言

创建会话和发送消息请求增加可选 `locale`：

```json
{
  "content": "检查这台主机",
  "locale": "zh-CN"
}
```

服务端兼容未携带 `locale` 的旧客户端，解析优先级：

```text
请求体中的合法 locale
  -> Accept-Language
  -> zh-CN
```

运行启动时把语言写入本次 RunInput 或运行元数据，编排器和 LLM prompt 使用该语言快照。语言优先级：

```text
用户在本轮明确要求的输出语言
  -> 本次运行 locale
  -> 用户输入语言推断
```

运行中的 SSE 事件不因界面中途切换而改变语言。历史消息不重写，新运行使用最新语言。工具名、参数名、枚举、call ID 和其他机器标识继续保持英文稳定形式。

服务端固定产生的澄清问题、审批标题、取消提示、上传摘要和错误助手消息也需要根据运行语言生成，不能继续硬编码中文。

## 8. 数据与配置影响

### 8.1 数据库

- 不新增表和字段。
- 通知复用已有 `metadata` JSONB 扩展 `i18n_key` 和 `i18n_params`。
- 智能助手运行语言优先保存到已有会话或运行 metadata；若当前运行模型没有可复用 metadata，再在实现设计中评估最小字段扩展。
- 历史数据不执行批量翻译和回填。

### 8.2 配置

- 不新增服务端环境变量。
- 前端本地存储键为 `aegis_locale`。
- 支持语言白名单由代码定义，V6.1 仅允许 `zh-CN` 和 `en-US`。
- 离线发布流程无需下载运行时语言资源，只需确保新增依赖和语言文件进入前端构建产物。

## 9. 失败处理

- 本地语言值非法：回退 `zh-CN` 并覆盖非法值。
- 英文资源缺少键：开发和测试阶段失败；生产环境回退对应中文键，不展示裸键。
- Element Plus 语言包加载失败：回退中文包，业务页面继续可用。
- 未知 API 错误码：展示本地化通用错误，不泄漏内部错误详情。
- 未知通知模板：展示数据库中的原始标题和正文。
- 智能助手请求缺少语言：按请求头或中文默认值运行。
- 切换语言时正在编辑表单：只更新标签，不清空输入、不重新挂载页面。
- 切换语言时智能助手正在流式输出：当前运行保持原语言，下一轮生效。

## 10. 安全与审计影响

- 语言参数使用固定白名单校验，不能作为模板路径、文件路径或动态代码输入。
- 不翻译命令、脚本、日志、证据和用户输入，避免改变执行及审计语义。
- 审计记录保存原始操作、原始错误码、模板键和参数；展示层翻译不改变审计事实。
- API 的英文错误展示不能扩大内部错误暴露范围。
- 通知模板参数按普通文本渲染，禁止使用未清洗 HTML。
- 国际化不改变现有权限、角色、认证、模式切换和危险操作审批流程。

## 11. 兼容性

- 中文保持默认语言，现有用户升级后界面行为不变。
- REST 的 `Accept-Language`、`error_code` 和 `params` 均为兼容扩展。
- 智能助手 `locale` 为可选字段，旧客户端仍可调用。
- 通知继续保留 `title` 和 `content`，旧前端不依赖新增 metadata。
- 路由路径、API 枚举、数据库值、proto 和 Agent 协议不变。
- 前端回滚后，服务端新增字段会被旧前端忽略。

## 12. 实施顺序

### 12.1 第一阶段：基础设施与应用框架

- 引入 Vue I18n 和语言资源骨架。
- 实现语言状态、持久化、Element Plus Config Provider 和 `LanguageSwitcher`。
- 完成 App、导航、路由、登录、首次改密和用户菜单迁移。
- 建立资源键完整性测试。

### 12.2 第二阶段：业务页面迁移

按领域迁移：

```text
通用组件
  -> 主机与资产
  -> 基线与任务
  -> 漏洞
  -> 异常检测与检测包
  -> 弱密码
  -> 系统配置与审计
  -> 智能助手
```

每个领域同时迁移模板文案、脚本文案、状态映射、消息框、图表、日期和相关测试，避免页面出现中英混杂的中间状态。

### 12.3 第三阶段：动态服务内容

- 增加 REST 语言头和错误码翻译。
- 为新通知增加语义模板键。
- 向智能助手运行传递语言并迁移服务端固定用户文案。
- 检查 api-server 和 dc 产生的前端可见文本；日志和内部错误不纳入界面翻译。

### 12.4 第四阶段：全量验证

- 执行原始中文回归。
- 执行英文页面、长文本和布局回归。
- 执行语言持久化、跨标签页、通知、错误和智能助手真实链路验证。
- 扫描生产前端代码中的裸界面文案，并维护只允许注释、测试数据和业务原始数据的白名单。

## 13. 测试设计

### 13.1 单元测试

- 支持语言解析、非法值回退和本地存储异常。
- `zh-CN` 与 `en-US` 资源键集合完全一致。
- 语言切换同步更新 Vue I18n、Element Plus、`html lang` 和请求语言头。
- 路由 `titleKey` 在两种语言下正确生成面包屑和页面标题。
- 状态、风险级别、日期、数字、相对时间和复数格式正确。
- API 已知错误码、未知错误码和 HTTP 兜底逻辑正确。
- 通知模板翻译、未知模板及历史通知回退正确。
- 智能助手创建和发送请求携带当前语言。

### 13.2 组件测试

- 语言按钮紧邻模式控件，中文显示 `EN`，英文显示 `中文`。
- 切换语言不改变当前模式和路由。
- 登录页和首次设置密码页能够独立切换语言。
- Element Plus 分页、日期选择器、空状态和弹窗同步更新。
- 英文长文案不覆盖按钮、表头或关键操作区域。
- 图表在切换后更新文案但不重新获取数据。

### 13.3 端到端测试

至少覆盖以下流程：

1. 中文登录，进入运维审计页面，切换英文并遍历所有一级导航。
2. 刷新页面、退出并重新登录，确认英文保持。
3. 切换智能体模式，确认会话、路由和上下文不丢失。
4. 英文模式创建智能助手新运行，确认新生成的用户可见内容使用英文。
5. 智能助手运行中切换中文，确认当前流不混合语言、下一轮使用中文。
6. 在中英文下触发成功提示、校验错误、HTTP 错误和确认框。
7. 验证新通知在两种语言下切换，历史通知保持原文。
8. 切回中文，确认全部核心流程与改造前一致。

## 14. 验收标准

- 顶部语言按钮位于“运维审计 / 智能体模式”控件右侧。
- 中英文切换无需刷新，不改变路由、模式和页面业务状态。
- 主应用、认证页面和全部业务模块的静态用户文案均可切换。
- Element Plus、日期、数字、相对时间、图表、tooltip 和无障碍文本同步切换。
- 刷新、退出和重新登录后保持用户语言选择。
- 中英文资源键一致，不存在未说明的裸界面中文或英文文案。
- API 已知错误以当前语言展示，未知错误安全回退。
- 新系统通知可以在当前语言下即时渲染；历史通知保持兼容。
- 新智能助手运行默认使用当前界面语言，历史消息及当前运行不被重写。
- 命令、脚本、日志、证据、标识符和用户业务数据不被错误翻译。
- 前端测试、lint、类型检查和构建通过；涉及后端的定向测试与构建通过。

## 15. 风险与控制

| 风险 | 控制措施 |
|:---|:---|
| 页面文案数量大，容易漏翻 | 按业务域迁移、资源键一致性测试、裸文案扫描和 E2E 遍历 |
| 英文文案较长导致布局溢出 | 固定关键控件尺寸、允许表头合理换行、英文视觉回归 |
| store 缓存翻译文本导致切换不更新 | store 只保存原始值，翻译在 computed 或展示层执行 |
| 服务端中文错误导致英文页面混杂 | 稳定 `error_code`、本地化映射和通用安全兜底 |
| 通知历史数据无法翻译 | 新通知使用模板键，历史通知明确回退原文 |
| 智能助手流中途混合语言 | 每次运行固定 locale 快照，切换只影响下一轮 |
| 翻译改变安全数据语义 | 明确业务数据边界，禁止翻译命令、脚本、日志和证据 |
| 离线环境依赖缺失 | 语言资源和依赖全部打入前端及离线发布产物 |

## 16. 回滚方案

- 前端可整体回滚语言按钮、Vue I18n 注册和翻译资源调用，中文原始资源继续作为默认展示来源。
- 服务端新增的 `Accept-Language` 解析、`error_code`、通知 metadata 和智能助手 `locale` 均为兼容扩展，可先保留而不影响旧前端。
- 不进行历史数据翻译和不可逆回填；通知 metadata 扩展无需数据库结构回滚。
- 若动态内容国际化出现问题，可暂时停用错误码或模板键消费，回退服务端原始中文 `message/title/content`，不影响业务数据和任务执行。
- 回滚不修改路由、权限、任务状态、Agent 协议或安全审计数据。
