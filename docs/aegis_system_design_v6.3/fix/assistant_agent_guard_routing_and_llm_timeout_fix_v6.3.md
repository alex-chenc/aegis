# Assistant Agent Guard 路由与 LLM 超时修复（V6.3）

## 问题

用户询问“目前 Codex 智能体有哪些安全问题”时，Assistant 会长时间停留在“开始执行任务”，最终返回扫描/修复类失败兜底。实际会话没有调用任何工具，Runtime 在模型计划生成阶段因外部 LLM 请求超时而结束；同时 Agent Guard 工具虽已注册，但没有对应的一层工作流卡，无法进入能力目录。

## 修复范围

- 增加 `agent_guard_observation` 和 `agent_guard_control` 两张闭合工作流卡；观察工作流只暴露姿态、脱敏证据、会话查询/分析和运行设置读取，控制工作流承载采集、配置修改和隔离动作。
- 对包含 Codex/Claude/智能体与安全风险语义的请求施加观察工作流契约；显式控制动作施加控制工作流契约，仍由能力映射、审批和后端服务执行。
- 意图识别与拆解分别使用 90 秒阶段上下文；无工具模型运行使用 90 秒任务预算、60 秒模型预算。固定计划的漏洞/弱口令长任务预算不变。
- Runtime LLM 适配器使用 `LLMRequest.Timeout` 创建请求上下文，避免底层 1200 秒默认超时覆盖阶段边界。
- 无工具分析失败时返回“分析未完成，未执行工具操作”的语义兜底，不再声称扫描、修复或验证失败。
- `AgentGuard.Scope.Investigate` 要求精确的 `scope_type` 与 `scope_id`；姿态/证据摘要不会被错误地当作这两个字段的 `previous_step` 生产者。缺少精确范围时工具被拒绝并提示补充，已有范围则由参数、意图范围、对象或上下文引用确定性绑定。
- 会话查询在完整列表前返回紧凑 `risk_summary`，包含高风险总数、活跃高风险数及每个高风险会话的精确 ID、状态、规则命中数和条目数。即使 Runtime 截断后续列表，总结阶段也能明确列出受影响对象；`risk_types_available=false` 明确禁止把风险等级或命中次数臆测成提示词注入、密钥泄漏等具体类别。
- 安全分析总结固定使用“结论、具体高风险、处置建议、证据边界”四段契约：首句给出总体风险，风险项逐项包含对象、证据、影响和验证状态，处置项使用 P0/P1/P2，并明确未执行建议。
- Assistant 前端新增安全结论卡片，结构化显示风险徽标、风险明细、处置优先级和证据边界；兼容历史长段落结论，并在所有模型文本进入 `v-html` 前完成 HTML 转义。

## 安全与兼容性

- 工作流仍是模型可见能力的闭合白名单；Agent Guard 控制能力不因观察请求自动暴露。
- 所有控制能力继续经过现有风险、审批、参数和后端所有权校验。
- 长时间漏洞扫描的固定计划与两小时终态观察窗口不改变。
- 未改变数据库结构、HTTP/gRPC 协议或已有工作流 ID。

## 验收标准

1. Codex 安全问题请求的显式工作流要求为 `agent_guard_observation`。
2. Agent Guard 观察/控制工作流可被精确解析，能力白名单不混用。
3. Runtime LLM 请求尊重调用级超时；超时测试在短时间内结束。
4. 无工具失败兜底不包含扫描/修复/验证类误导文本。
5. api-server 定向测试、构建、服务健康检查和 Assistant 路由冒烟通过。
6. 缺少 Agent Guard 精确范围时不得生成无生产者的 `previous_step` 依赖；带有精确范围时编译计划通过依赖校验。
7. 会话查询结果被截断时仍可从前置 `risk_summary` 取得全部（不超过当前页 50 条）高风险会话摘要；未提供规则类别时结论必须明确“具体类型待核实”。
8. 新结论在桌面端和窄屏下均按四个区块呈现，历史安全长段落可降级分区，模型输出的 HTML 不得作为 DOM 节点执行。
