## 1. 架构设计原则

### 1.1 设计目标

1. **高内聚低耦合**: 各服务职责明确，独立部署演进
2. **资源高效**: Agent端资源占用 < 1C1G
3. **智能分布**: 边缘预处理 + 云端智能分析
4. **渐进式演进**: 支持单体→微服务平滑过渡

### 1.2 核心思想

**不在Agent端运行大模型，而是通过架构设计实现"智能"效果：**

| 传统方式 | V5.5优化方式 |
|----------|--------------|
| Agent采集100%原始数据上报 | 本地智能压缩，只上报特征数据 |
| 所有事件等待后端处理 | 本地决策，高危事件立即阻断 |
| 事件无差别处理 | 分级处理，紧急事件优先 |
| 网络流量大、延迟高 | 减少90%网络流量，延迟降低90% |

### 4.2 命令下发流

```
Frontend → API Server → Server (APIServerToServer:19094) → Agent执行 → 结果回收 → 存储
```

**详细流程**:
1. Frontend通过HTTP请求API Server
2. API Server通过gRPC调用Server的APIServerToServer服务 (端口19094)
3. Server通过双向流将命令下发到对应Agent (端口19090)
4. Agent执行完成后通过同一gRPC流返回结果
5. Server将结果通过APIServerToServer返回给API Server

## 5. Agent智能设计

### 5.1 本地智能模块

```go
// 本地智能处理核心
type LocalIntelligence struct {
    // 统计异常检测
    windowStats *SlidingWindowStats

    // 规则优先级引擎
    priorityEngine *PriorityEngine

    // 特征提取器
    featureExtractor *FeatureExtractor

    // 本地决策引擎
    decisionEngine *DecisionEngine

    // 智能通信器
    communicator *SmartCommunicator
}

// 滑动窗口统计 - 检测频率异常
type SlidingWindowStats struct {
    windowSize time.Duration
    maxEvents  int
    counters   map[string]*WindowCounter
    mu         sync.RWMutex
}

type WindowCounter struct {
    events    []time.Time
    threshold int
}

// 优先级引擎 - 事件分级
type PriorityEngine struct {
    rules []PriorityRule
}

type PriorityRule struct {
    Match   func(Event) bool
    Level   PriorityLevel  // CRITICAL, HIGH, MEDIUM, LOW
    Score   int
}
```

### 5.2 本地决策规则

| 场景 | 决策 | 行为 |
|------|------|------|
| 匹配阻断规则 | 本地阻断 | 立即kill进程 + 上报 |
| 频率异常 | 高优先级上报 | 标记为HIGH + 实时上报 |
| 新进程 | 提取特征上报 | 正常处理 + 等待后端 |
| 白名单进程 | 忽略 | 不上报 |
| 黑名单进程 | 本地阻断 | 立即kill + 上报 |

### 5.3 智能压缩算法

```go
// 特征提取 - 将完整事件压缩为特征向量
type FeatureExtractor struct{}

func (fe *FeatureExtractor) Extract(event Event) EventFeatures {
    return EventFeatures{
        // 基础特征 (64 bytes)
        EventType:   event.EventType,
        ProcessName: hash(event.ProcessName),
        UID:         event.UID,

        // 统计特征 (32 bytes)
        FrequencyScore:  fe.calcFrequency(event),
        ProcessTreeScore: fe.calcProcessTree(event),

        // 上下文特征 (64 bytes)
        TimeOfDay:        event.Timestamp % 86400 / 3600,
        IsSystemProcess:  event.UID < 1000,
        HasNetworkAccess: fe.checkNetwork(event),
    }
}

// 计算频率得分
func (fe *FeatureExtractor) calcFrequency(event Event) float64 {
    // 简化: 基于滑动窗口计算
    count := globalStats.GetCount(event.ProcessName, 5*time.Minute)
    return float64(count) / 100.0
}
```

## 7. 服务发现与通信

### 7.1 服务注册

| 服务 | 注册方式 | 健康检查 |
|------|----------|----------|
| api-server | Nginx upstream | /health |
| server | Redis + DNS | gRPC health check |
| dc | Redis | gRPC health check |

### 7.2 服务间通信

```
API Server → Server: gRPC (APIServerToServer端口19094)
Server → DC: Kafka (topic: aegis.security.events, aegis.block.commands)
Server → Agent: gRPC双向流 (端口19090)
DC → API Server: gRPC或共享数据库
```

### 7.3 Kafka Topics

| Topic | 生产者 | 消费者 | 用途 |
|-------|--------|--------|------|
| aegis.security.events | Server | DC | 运行时安全事件 |
| aegis.block.commands | DC | Server | 阻断命令 |
| aegis.rule.updates | API Server | Server | 规则更新 |

## 8. 容错与降级

### 8.1 故障处理

| 故障场景 | 处理策略 |
|----------|----------|
| Agent Hub宕机 | Agent本地缓存策略 + 重连 |
| Pipeline Service宕机 | 事件在Kafka积压 + 恢复后处理 |
| LLM服务不可用 | 使用规则引擎降级处理 |
| 数据库不可用 | 缓存关键数据 + 告警 |

### 8.2 Agent降级策略

```
正常模式:
  Agent → 本地智能 → 压缩上报 → Backend处理

降级模式 (Backend不可达):
  Agent → 本地阻断规则 → 执行阻断 → 本地日志

恢复后:
  上报离线期间事件 → 同步最新策略
```
