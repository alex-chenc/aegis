# Aegis V6.0 PRD: 双模智能安全指挥台

**版本**: 6.0  
**日期**: 2026-05-29  
**状态**: 设计中

---

## 1. 背景

当前 Aegis V5.8 已具备主机资产、基线检查、漏洞检查、异常检测、AI 分析、阻断策略、动态 eBPF 检测包、模型配置和审计日志等能力。功能完整，但操作仍然以页面和表单为主。安全运营人员在真实场景中经常需要跨多个页面完成一个目标：

- 从告警追溯到主机、进程、网络连接、历史日志。
- 从 CVE 查询受影响主机，生成 POC 或修复脚本，再下发任务并跟踪结果。
- 从 AI 生成动态检测包草稿，人工修改后构建、审核、签名、启用。
- 从任务失败日志定位原因，再调整脚本或重新下发。

V6.0 希望通过智能体模式把这些跨页面流程变成自然语言任务，同时保留普通模式的可视化和精确控制。

---

## 2. 产品目标

### 2.1 主目标

建立“普通模式 + 智能模式”的双模工作台：

1. 普通模式保留全部现有页面。
2. 智能模式支持用户用自然语言完成所有核心安全运营功能。
3. 两种模式共享同一业务数据、权限、审计和执行链路。
4. 高风险动作必须经用户审批，智能体不能绕过安全边界。
5. 所有智能体计划、工具调用、审批和结果可回放、可审计。
6. 智能体工具支持三种审批模式：请求批准、白名单、完全权限。

### 2.2 用户价值

| 用户 | 当前痛点 | V6.0 价值 |
|:---|:---|:---|
| 安全运营人员 | 需要跨页面查询、筛选、判断、执行 | 对话发起任务，智能体自动查询和汇总 |
| 安全分析师 | 告警分析依赖经验，链路长 | 自动计划调查步骤，调用 agent 工具收集证据 |
| 安全开发人员 | 规则和检测包生产步骤多 | 智能体生成草稿、解释构建失败、提出修改建议 |
| 管理员 | 高危动作需要可控和可审计 | 审批卡片集中展示风险、影响范围和执行结果 |

## 3. 范围

### 3.1 范围内

- 新增全局智能模式工作台 `/assistant`。
- 新增普通/智能模式切换入口。
- 在现有页面加入“交给智能体”入口。
- 新增智能体会话、消息、上下文对象、工具调用、审批和记忆数据模型。
- 新增工具目录和工具注册中心，将现有业务能力封装成智能体工具。
- 新增意图路由和工具检索，避免把全量工具一次性暴露给大模型。
- 新增外接 MCP 数据源配置，支持通过已配置 MCP 数据源查询 SIEM、CMDB、EDR、工单、威胁情报等外部数据并融合分析。
- 新增主机攻击研判智能体 Profile，融合资产、漏洞、基线、告警、Agent 实时证据和外部 MCP 证据，输出是否被攻击、入口、攻击路径和证据链。
- 新增审批网关，高风险动作必须等待用户确认。
- 新增智能体执行 SSE 事件，用于展示计划、步骤、工具调用、审批和最终结果。
- 复用当前模型配置、agent-runtime、server/agent gRPC、业务 service 和审计日志。

### 3.2 范围外

- 不在 V6.0 第一版新增独立 `assistant` 微服务。
- 不允许智能体绕过 service 直接写数据库。
- 不允许智能体自动签名发布 DetectionPackage。
- 不允许智能体自动启用动态 eBPF 检测包。
- 不允许智能体自动修改 hook allowlist。
- 不做跨租户、多组织、多工作空间。
- 不做完全自主无人值守处置。

## 4. 模式定义

### 4.1 普通模式

普通模式对应当前 Aegis 控制台：

```text
主机列表
智能基线检查与修复
智能漏洞检查与修复
智能异常检测
系统配置
外接 MCP 数据源
```

普通模式适合：

- 明确对象的批量管理。
- 表格筛选、排序、分页。
- 详情编辑。
- 精确配置。
- 管理员审批和审计追踪。

### 4.2 智能模式

智能模式新增入口：

```text
/assistant
```

智能模式适合：

- 用户只知道目标，不知道页面路径。
- 需要跨模块组合操作。
- 需要分析、总结、解释和建议。
- 需要把复杂任务拆成多个步骤。
- 需要持续跟踪任务结果。

| DET-6 | 用户说“把 T1059.004 的 AI 自动阻断打开” | 生成 high 审批，批准后更新阻断策略 |

### 5.4.1 主机攻击研判

| 编号 | 用户故事 | 验收标准 |
|:---|:---|:---|
| HAI-1 | 用户从主机详情点击“攻击研判” | 自动创建 `host_attack_investigation` 会话，带入 host_id、hostname、ip、业务标签 |
| HAI-2 | 用户问“这台主机是不是被攻击了” | 返回 `confirmed_compromised/suspicious/likely_benign/insufficient_evidence` 判断、分数、置信度和关键证据 |
| HAI-3 | 用户问“攻击入口是什么” | 输出入口候选列表，关联漏洞、基线、暴露服务、登录、进程、网络和外部证据，按置信度排序 |
| HAI-4 | 用户问“攻击是怎么进行的” | 输出攻击时间线、攻击路径图、MITRE 技术映射、关键进程/文件/网络证据 |
| HAI-5 | 用户问“漏洞和基线是不是入口原因” | 自动关联主机漏洞、基线失败项、告警时间和服务暴露情况，输出支持证据和反证 |
| HAI-6 | 用户要求结合 SIEM/CMDB/EDR | 智能体通过 `ExternalMCP.*` 内部工具查询已配置数据源，结果脱敏、截断、标注来源后参与研判 |
| HAI-7 | 用户要求“确认后阻断/修复” | 智能体只能建议或发起对应审批工具；未审批前不能声称已经执行 |
| HAI-8 | 证据不足 | 必须明确“证据不足以确认”，列出缺失数据和下一步取证建议 |

## 6. 智能体任务类型

| 类型 | 说明 | 默认工具域 | 白名单模式默认行为 |
|:---|:---|:---|:---:|
| `investigation` | 告警或主机调查 | host, detection, agent_tool | 是，只读工具 |
| `host_attack_investigation` | 主机是否被攻击、入口和路径研判 | investigation, host, detection, vulnerability, baseline, agent_tool, external_mcp | 内部只读研判默认可执行；外部数据和处置动作按审批策略 |
| `operations` | 创建扫描、检查、构建任务 | vulnerability, baseline, package | 部分需要确认 |
| `generation` | 生成脚本、规则、检测包草稿 | script, rule, package | 是，但保存/执行按风险审批 |
| `remediation` | 修复、阻断、禁用、启用 | task, block, package | 默认不进白名单，需审批 |
| `configuration` | 模型配置、审计配置、hook allowlist | config, audit | 写操作默认不进白名单，需审批 |
| `external_data_analysis` | 融合外部 SIEM/CMDB/EDR/工单/威胁情报 | external_mcp, detection, host | 查询外部数据默认需审批或白名单配置 |
| `explanation` | 解释页面数据、日志、策略 | all readonly | 是 |

## 7. 风险分级与审批

| 风险等级 | 示例工具 | 白名单模式默认策略 |
|:---|:---|:---|
| readonly | 查询主机、查询告警、查询任务 | 默认白名单，自动执行 |
| low | 生成草稿、总结、解释、RAG 检索 | 可默认白名单，自动执行 |
| medium | 创建扫描、提交构建、重新下发任务 | 可配置是否审批，默认需要用户确认 |
| high | 执行修复、POC、禁用规则、修改策略 | 默认不进白名单，需要审批 |
| critical | 阻断、签名发布、启用检测包、修改 hook allowlist | 默认不进白名单，需要审批，必须写审计 |

上表是 `whitelist` 模式的默认安全策略。`request_approval` 模式下所有工具都要审批；`full_access` 模式下审批要求由管理员显式关闭，但 RBAC、工具注册校验、工具启用、参数校验和审计仍然生效。

### 7.1 智能体工具审批模式

| 模式 | 产品名称 | 行为 |
|:---|:---|:---|
| `request_approval` | 请求批准 | 所有工具调用都弹出审批，批准并执行成功后智能体继续 |
| `whitelist` | 白名单 | 白名单工具自动执行，非白名单工具弹出审批 |
| `full_access` | 完全权限 | 所有被智能体本轮选中的工具都可直接执行 |

默认使用 `whitelist`。系统初始化一批 readonly/low 工具为白名单，高危和关键工具默认不在白名单。

配置页必须展示全部智能体工具：

- 工具名称。
- 工具详情。
- 领域和操作类型。
- 风险等级。
- 参数摘要。
- 是否默认白名单。
- 是否加入当前白名单。
- 最近更新时间。

审批卡片必须展示：

- 动作名称。
- 目标对象。
- 影响范围。
- 风险等级。
- 输入参数摘要。
- 预期结果。

### 7.2 外接 MCP 数据源需求

| 编号 | 用户故事 | 验收标准 |
|:---|:---|:---|
| MCP-1 | 管理员在配置页新增 SIEM MCP 数据源 | 保存 endpoint、认证方式、查询上限，凭据加密保存且列表脱敏展示 |
| MCP-2 | 管理员点击测试连接 | 后端实际访问 MCP endpoint，返回成功/失败、延迟、错误摘要 |
| MCP-3 | 管理员同步 schema | 保存外部 MCP tool/schema 摘要，供智能体做数据源选择 |
| MCP-4 | 用户要求关联 Aegis 告警和外部 SIEM/CMDB | 智能体只选择相关数据源，查询结果脱敏后进入大模型上下文 |
| MCP-5 | 外部 MCP 返回疑似 prompt injection 文本 | 模型必须当作普通数据，不改变系统指令、不泄露凭据 |
| MCP-6 | 外部数据源查询失败 | 最终回答必须说明失败来源和不确定性，不能编造外部证据 |

## 9. 非功能需求

| 类型 | 需求 |
|:---|:---|
| 性能 | 会话列表 P95 小于 300ms，发送消息首个 SSE 事件 P95 小于 2s |
| 可用性 | LLM 不可用时，普通模式不受影响，智能模式返回明确错误 |
| 可追溯 | 每次工具调用和审批必须落库 |
| 安全 | critical 工具默认不进白名单；只有管理员切到 `full_access` 或显式加入白名单后才可免审批，同时必须保留审计 |
| 工具上下文 | 单次注入 agent-runtime 的工具默认不超过 24 个，支持 `Tool.Search` 扩展 |
| 工具权限 | 配置页可切换请求批准、白名单、完全权限，并维护工具白名单 |
| 外部数据安全 | 外接 MCP 查询结果进入大模型前必须脱敏、截断、标注来源，外部内容视为不可信数据 |
| 研判可信度 | 主机攻击研判必须区分事实、推断和假设；关键结论必须引用 evidence_id 或说明证据不足 |
| 兼容 | 不破坏 V5.8 API、表结构和前端路由 |
| 可回放 | 历史会话可恢复消息、计划、工具调用、审批和结果 |
| 可中断 | 长任务支持取消，取消后停止后续工具调用 |

## 10. 验收标准

1. 用户可以在 `/assistant` 创建全局智能体会话。
2. 用户可以从普通页面带上下文进入智能模式。
3. 智能体能查询主机、任务、告警、漏洞、检测包。
4. 智能体能生成结构化计划并通过 SSE 展示。
5. 智能体工具调用有风险等级和执行记录。
6. 高风险工具在 `request_approval` 或 `whitelist` 非白名单状态下必须生成审批，未审批不能执行。
7. 审批通过后执行现有 service 能力，业务数据在普通模式可见。
8. DetectionPackage 签名和启用必须拆成两个独立工具调用；需要审批时拆成两个独立审批。
9. 配置页可以查看全部智能体工具并维护白名单。
10. `request_approval` 模式下所有工具都必须审批。
11. `whitelist` 模式下白名单工具免审批，非白名单工具审批。
12. `full_access` 模式下所有被注入工具免审批但保留审计。
13. 动态检测包、Sigma 规则、阻断策略、阻断记录均可由智能体查询和按审批执行。
