## 2. 产品概述

AI基线检查系统是一个面向运维和安全工程师的内部管理平台。它旨在通过结合大语言模型（LLM）的智能解析能力和 Agent 的自动化执行能力，实现服务器基线配置的智能检查与自动修复。

**核心特性**：
- **智能文档解析**：上传基线文档（PDF、Word、YAML），LLM 自动解析为检查/修复规则
- **智能脚本生成**：点击检测/修复按钮，LLM 自动生成可执行的 Shell 脚本
- **任务进度追踪**：实时查看任务执行状态，包括脚本内容、执行结果、错误信息
- **自动自愈修复**：当脚本执行失败时，LLM 分析错误原因并自动生成修复后的脚本

## 3. 核心用户与场景

*   **核心用户**: 系统管理员、运维工程师、安全合规工程师。
*   **核心场景**:
    *   **批量主机纳管**: 用户需要快速、便捷地将数百台服务器接入系统进行统一管理。
    *   **基线模板解析**: 用户希望直接利用现有的安全基线文档，而不是手动编写检查脚本。
    *   **自动化检查与修复**: 用户需要对纳管的主机执行自动化的基线检查，并对不合规项进行一键修复。

## 4. 功能需求详述

系统在功能上高度收敛，仅包含三个核心工作界面，以提供专注、高效的用户体验。

### 4.1 页面一：系统配置与 Agent 安装页

**页面路径**: `/settings`

#### 4.1.1 功能目标

提供系统与外部服务（大模型）连接的配置入口，并为用户提供将主机纳管到本系统的标准化安装命令。

#### 4.1.2 界面布局与组件

页面采用上下布局，分为两个卡片区域：

1.  **大模型配置 (LLM Configuration)**
2.  **Agent 纳管 (Agent Installation)**

#### 4.1.3 详细交互逻辑

**大模型配置卡片**:

*   **组件**:
    *   **API Key 输入框**: `ElInput`，`type="password"`，`show-password`。用于输入大模型服务的认证密钥。
    *   **Base URL 输入框**: `ElInput`。用于输入大模型服务的 API 端点，默认为 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
    *   **连通性测试按钮**: `ElButton`。用于验证配置是否正确。
    *   **保存按钮**: `ElButton`，`type="primary"`。默认禁用。
*   **流程**:
    1.  **页面加载**: 前端调用 `GET /api/v1/config/llm` 接口获取当前配置。API Key 以脱敏形式（例如 `sk-xxxx...1234`）填充输入框，Base URL 正常填充。
    2.  **用户编辑**: 用户修改任一输入框内容后，“保存”按钮保持禁用状态。
    3.  **连通性测试**: 用户点击“连通性测试”按钮。
        *   按钮文本变为“测试中...”，并进入加载状态。
        *   前端调用 `POST /api/v1/config/llm/test` 接口，将当前输入框中的内容作为请求体发送。
        *   **测试成功**: 按钮恢复原状，并在按钮旁边显示一个绿色的成功图标和“连接成功”的文字提示。此时，“保存”按钮变为可用状态。
        *   **测试失败**: 按钮恢复原状，并在按钮旁边显示一个红色的失败图标和从后端返回的具体错误信息（如“认证失败，请检查 API Key”或“网络不通，请检查 Base URL 和服务器网络”）。“保存”按钮保持禁用。
    4.  **保存配置**: 用户在测试成功后，点击“保存”按钮。
        *   前端调用 `POST /api/v1/config/llm` 接口，提交表单。
        *   保存成功后，显示一个全局的成功消息提示（“配置已保存”），并将新获取的脱敏 API Key 更新到输入框中。

**Agent 纳管卡片**:

*   **组件**:
    *   **命令显示框**: 一个只读的代码块，背景为深色，模拟终端样式。
    *   **复制按钮**: `ElButton`。位于代码块的右上角。
*   **流程**:
    1.  **页面加载**: 前端调用 `GET /api/v1/agent/install-command` 接口获取一键安装命令。
    2.  **命令展示**: 后端返回的命令（例如 `curl -sSL http://<Server_IP>/api/v1/agent/install.sh | sudo bash`）被完整地展示在代码块中。
    3.  **复制命令**: 用户点击“复制”按钮，命令内容被复制到剪贴板，并显示一个短暂的“已复制”提示。
    4.  **辅助说明**: 代码块下方有一行小字说明：“请使用 root 权限在目标主机上执行此命令以完成安装。”

### 4.2 页面二：资产展示大盘

**页面路径**: `/dashboard/hosts`

#### 4.2.1 功能目标

以清晰、简洁的列表形式，展示所有已接入系统的主机资产及其核心状态。

#### 4.2.2 界面布局与组件

页面主要由**搜索/操作区**和**数据表格区**组成。

*   **搜索/操作区**:
    *   **搜索框**: `ElInput`，支持按 IP 地址或主机名进行模糊搜索。
    *   **刷新按钮**: `ElButton`，图标为刷新图标。
*   **数据表格区**:
    *   **表格**: `ElTable`，用于展示主机列表。
    *   **分页组件**: `ElPagination`，位于表格下方。

#### 4.2.3 详细交互逻辑

*   **数据加载与刷新**:
    1.  **首次进入**: 页面挂载后（`onMounted`），自动调用 `fetchHosts` action，向后端 `GET /api/v1/hosts` 请求第一页数据。表格显示加载中（`loading`）状态。
    2.  **手动刷新**: 用户点击右上角的“刷新”按钮，再次调用 `fetchHosts` action，请求当前页的最新数据。表格进入加载中状态，完成后更新数据。
    3.  **无实时更新**: 页面数据在用户不操作的情况下不会自动变化。
*   **表格列定义**:
    | 列标题 | 字段名 | 展示方式 |
    |:---|:---|:---|
| 在线状态 | `status` | 一个圆形状态灯。`online` 为绿色，`offline` 为灰色。 |
| IP 地址 | `ip_address` | 纯文本。 |
| 主机名 | `hostname` | 纯文本。 |
| 系统类型 | `os_type` | 纯文本，例如 `linux`。 |
| Agent 版本 | `agent_version` | 纯文本，例如 `v1.5.0`。 |
| 最后心跳时间 | `last_heartbeat_at` | 格式化后的时间字符串，例如 `2026-03-05 14:30:00`。 |
| 操作 | (无) | 一个 `ElButton`，文本为“详情”，点击后跳转到该主机的详情页（预留功能）。 |
*   **搜索功能**:
    1.  用户在搜索框中输入关键字后按回车，或点击搜索图标。
    2.  前端以用户输入的关键字作为 `query` 参数，调用 `fetchHosts` action，请求第一页的搜索结果。
*   **分页功能**:
    1.  用户点击页码或改变每页显示数量。
    2.  前端以新的页码 (`page`) 和每页数量 (`pageSize`) 作为参数，调用 `fetchHosts` action，请求对应页的数据。

### 4.3 页面三：基线检查工作台

**页面路径**: `/workbench`

#### 4.3.1 功能目标

提供一个从模板上传、解析、规则选择、任务下发到结果查看的完整闭环操作空间。

#### 4.3.2 界面布局与组件

页面采用左右布局：

*   **左侧：模板与规则区**
    *   模板上传组件
    *   模板列表
    *   规则列表
*   **右侧：主机与执行区**
    *   主机选择器
    *   执行操作按钮
    *   日志输出终端

#### 4.3.3 详细交互逻辑

*   **模板上传与解析**:
    1.  **上传**: 用户将文件拖拽到上传区域，或点击选择文件。前端调用 `POST /api/v1/templates/upload` 接口。
    2.  **解析**: 上传成功后，后端开始异步解析。前端轮询 `GET /api/v1/templates/{id}/status` 接口获取解析状态。界面显示"解析中，请稍候..."。
    3.  **结果展示**: 解析成功后，左侧的"模板列表"中新增一个条目。用户点击该模板，下方的"规则列表"会加载并展示从该模板中解析出的所有基线规则（标题、检测内容、修复内容）。
*   **主机选择**:
    *   右侧提供一个可搜索的主机选择穿梭框或带复选框的表格，用户在此选择要执行任务的目标主机。
*   **任务执行**:
    1.  用户在左侧选择一条规则，在右侧选择一个或多个主机。
    2.  点击"执行检查"按钮。按钮进入加载状态并禁用。
    3.  前端调用 `POST /api/v1/tasks/run-check` 接口，请求体包含 `rule_id` 和 `host_ids`。
    4.  **日志展示**: 右下角的"日志输出终端"开始轮询 `GET /api/v1/tasks/{task_id}/logs` 接口，并将获取到的日志（stdout, stderr）实时追加到终端中。
    5.  **检查完成**: 任务完成后，日志终端显示最终结果。如果检查结果为 `false`（不合规），则"执行修复"按钮变为可用状态。
*   **修复与自愈**:
    1.  用户点击"执行修复"按钮，流程与"执行检查"类似。
    2.  如果脚本执行过程中发生错误（例如 `command not found`），后端会启动自愈流程。此时，日志终端应明确打印出系统提示："脚本执行失败，正在尝试 AI 自我修复... (第 1/3 次)"。
    3.  后端完成自愈并重新下发任务后，日志终端会清空，并开始展示新脚本的执行日志。
*   **脚本编辑**:
    1.  规则列表中新增"默认脚本"列，包含"检测脚本"和"修复脚本"两个按钮，按钮上下对齐排列。
    2.  **脚本状态**分为四种：
        - **待生成**：按钮可点击，点击后自动调用LLM生成脚本
        - **生成中**：按钮禁用并显示加载状态，不可点击
        - **已生成**：按钮可点击，点击打开编辑对话框显示已有脚本
        - **生成失败**：按钮显示红色，鼠标悬浮时显示失败原因
    3.  点击按钮打开脚本编辑对话框：
        - **待生成状态**：自动调用LLM生成脚本，状态变为"生成中"
        - **已生成状态**：直接显示脚本内容，支持编辑和保存
        - **生成失败状态**：点击可重新生成脚本
    4.  编辑器使用等宽字体，支持语法高亮风格显示
    5.  点击"保存"按钮调用 `PUT /api/v1/rules/{id}/scripts` 接口保存脚本
    6.  规则列表标题栏显示规则总数和已选规则数量，全选按钮使用表格内置的复选框功能
*   **批量脚本生成**:
    1.  每个文件下的规则列表上方显示"一键生成检测脚本"和"一键生成修复脚本"两个按钮
    2.  点击按钮调用 `POST /api/v1/templates/{id}/generate-scripts` 接口
    3.  后端以并发数2的方式批量生成脚本（通过队列控制）
    4.  生成过程中规则状态实时更新（pending → generating → generated/failed）
    5.  接口返回：总数、已排队数、已跳过数、已存在数
*   **规则列表分页**:
    1.  每个文件下的规则表格支持分页，默认每页10条
    2.  分页组件显示在表格下方
    3.  分页状态独立维护，不同文件的规则列表分页互不影响
*   **规则内容显示**:
    1.  规则表格新增"检测内容"和"修复方法"两列
    2.  内容过长时截断显示（如超过30字符），悬浮显示完整内容
    3.  支持tooltip查看完整内容
*   **规则删除**:
    1.  规则列表操作列新增"删除"按钮
    2.  点击删除时，前端先调用 `GET /api/v1/rules/{id}/has-tasks` 检查是否有关联任务
    3.  如果有关联任务，显示错误提示"该规则有关联任务，无法删除"
    4.  如果无关联任务，显示确认对话框，用户确认后删除规则

#### 4.4.2 界面布局与组件

页面采用单卡片布局：

*   **过滤栏**: 状态过滤、类型过滤、搜索框
*   **任务列表表格**: 显示任务组概要信息
*   **分页组件**: 支持分页浏览

#### 4.4.3 详细交互逻辑

*   **数据加载**:
    1.  页面加载时自动调用 `GET /api/v1/tasks` 接口获取任务组列表。
    2.  支持分页参数：`page`, `page_size`。

*   **过滤功能**:
    1.  **状态过滤**: 支持按任务状态过滤（pending/running/success/failed/partial）。
    2.  **类型过滤**: 支持按任务类型过滤（check/fix）。
    3.  **搜索功能**: 支持按规则名称模糊搜索。

*   **任务列表展示**:
    | 列标题 | 字段名 | 展示方式 |
    |:---|:---|:---|
    | 选择框 | - | 复选框，用于批量操作 |
    | 任务组ID | `task_group_id` | 截断显示前8位，点击可跳转到任务详情页 |
    | 类型 | `task_type` | Tag 标签，检测为蓝色，修复为橙色 |
    | 任务数 | `task_count` | 纯文本 |
    | 进度 | - | 显示成功/失败/待执行/执行中数量 |
    | 状态 | `status` | Tag 标签，不同状态不同颜色 |
    | 创建时间 | `created_at` | 格式化时间 |
    | 操作 | - | "详情"按钮，跳转到任务详情页；"删除"按钮 |

*   **删除功能**:
    1.  **单个删除**: 操作列的"删除"按钮，仅已完成/失败的任务可删除，运行中的任务删除按钮置灰
    2.  **批量删除**: 表格上方显示"批量删除"按钮，显示已选择的数量
    3.  删除前显示确认对话框
    4.  批量删除时自动跳过运行中的任务，并在结果中提示跳过数量

*   **状态样式**:
    *   `pending` - 灰色 info
    *   `running` - 橙色 warning
    *   `success` - 绿色 success
    *   `failed` - 红色 danger
    *   `partial` - 橙色 warning

*   **刷新功能**:
    *   用户点击"刷新"按钮，重新获取当前页数据。

#### 4.5.2 界面布局与组件

*   **任务进度卡片**: 显示总体进度统计
*   **任务列表表格**: 显示每个子任务的详细信息

#### 4.5.3 详细交互逻辑

*   **进度展示**:
    *   使用统计卡片显示：总任务数、待执行、执行中、成功、失败。
    *   使用进度条显示完成百分比。

*   **自动刷新**:
    *   当有任务处于 pending 或 running 状态时，每 3 秒自动刷新一次。

*   **任务列表展示**:
    | 列标题 | 展示内容 |
    |:---|:---|
    | 规则标题 | 关联的基线规则名称 |
    | 主机 | 主机名和 IP 地址 |
    | 类型 | 检测/修复 |
    | 状态 | pending/running/success/failed |
    | 脚本 | "查看脚本"按钮 |
    | 结果 | "查看结果"按钮 |
    | 操作 | 自愈修复按钮（仅失败状态显示） |

*   **脚本查看**:
    *   点击"查看脚本"按钮，弹窗显示脚本内容。

*   **结果查看**:
    *   点击"查看结果"按钮，弹窗显示 stdout、stderr、exit_code。

*   **自愈修复**:
    *   当任务状态为 `failed` 时，显示"自愈修复"按钮。
    *   点击按钮后，系统将：
        1. 调用 `POST /api/v1/tasks/:id/heal` 接口触发自愈修复
        2. 后端创建自愈修复记录，启动后台 Worker 处理
        3. Worker 调用 LLM 根据错误信息生成修复后的脚本
        4. 修复成功后，自动更新规则的 `generated_check_script` 或 `generated_fix_script`
        5. 脚本版本记录存入 `script_versions` 表
    *   自愈修复最多重试 3 次，每次 LLM 调用超时时间为 120 秒
    *   用户可在前端查看修复进度（healing 状态）和结果
    *   **状态显示**（根据任务类型区分）:
        - 检测任务：检测中、检测成功、检测失败、脚本修复中、脚本修复成功、脚本修复失败
        - 修复任务：修复中、修复成功、修复失败、脚本修复中、脚本修复成功、脚本修复失败
    *   **脚本查看逻辑**: 脚本修复中状态时脚本按钮置灰不可查看，其他状态可正常查看
    *   **重新下发**: 仅在"检测失败"、"修复失败"和"脚本修复成功"状态时显示重新下发按钮
    *   **修复建议**: 用户可点击修复建议按钮，输入修复建议后发送给大模型进行脚本修复
    *   **删除任务**: 每个任务行都有删除按钮，点击后确认删除
    *   **执行超时**: 任务执行超过5分钟自动标记为失败
