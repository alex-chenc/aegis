## 4. 系统架构概览

系统分为四个核心层次，各层次之间通过明确定义的协议进行通讯。

**前端展示层**（Vue 3 + Nginx）负责提供用户界面，通过 RESTful API 与后端交互。Nginx 同时承担静态资源托管和 API 反向代理的双重职责。数据更新依赖用户操作显式触发，不使用 WebSocket。

**后端核心层**（Go + Gin + gRPC）是系统的中枢，由 HTTP 服务器（端口 8080）和 gRPC 服务器（端口 9090）两部分组成。HTTP 服务器处理前端请求，gRPC 服务器管理 Agent 连接。后端内部包含六大核心模块：LLM 交互模块（负责与通义千问 API 通讯）、文件解析模块（支持 PDF/Word/YAML/Excel/TXT 五种格式）、模板解析服务（编排文件解析和 LLM 规则提取的流水线）、脚本生成服务（自动生成检查和修复 Shell 脚本）、自愈修复服务（基于 LLM 的脚本自动修复，最多 3 次重试）和任务编排服务（管理任务下发和结果处理）。

**Agent 执行层**（Go 静态二进制）是部署在目标主机上的轻量级守护进程，通过 gRPC 双向流与后端保持长连接。Agent 负责上报身份信息（IP、主机名、系统类型）、维持 30 秒周期的心跳和执行后端下发的 Shell 脚本。Agent 通过 MinIO 分发，支持 linux/amd64 和 linux/arm64 两种架构。

**数据与存储层**由三个组件组成：PostgreSQL 14（持久化 7 张业务表的所有数据）、Redis 7（缓存 Agent 在线状态、任务实时日志、模板解析进度和 LLM 配置）和 MinIO（存储基线模板文件、Agent 二进制包和 LLM 生成的脚本文件，共 3 个 Bucket）。

## 5. 核心业务流程

### 5.1 基线模板解析流程

用户上传基线文档后，系统自动完成以下流水线：文件上传到 MinIO → 文件内容解析（PDF/Word/YAML/Excel/TXT）→ 文本预处理（去噪、分片）→ 构建 LLM 提示词 → 调用通义千问提取基线规则 → 解析 LLM 返回的 JSON → 批量写入数据库 → 自动触发检查脚本和修复脚本生成。

### 5.2 脚本自动生成流程

规则入库后，系统自动为每条规则生成检查脚本和修复脚本：构建脚本生成 Prompt → 调用 LLM 生成 Shell 脚本 → 安全性校验（危险命令检测等 5 项检查）→ 脚本版本记录 → 存储到数据库和 MinIO。

### 5.3 自愈修复流程

脚本执行失败时，系统自动启动自愈：捕获错误信息 → 构建自愈 Prompt（含原始脚本、错误输出、执行环境和历史修复尝试）→ 调用 LLM 生成修复脚本 → 安全性校验 → 重新下发执行 → 判断结果（成功则更新脚本版本，失败且未达 3 次上限则继续重试）。
