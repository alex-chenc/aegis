# 自动化基线检查与自愈系统 综合设计文档 (V1.6 全面重构)

## 1. 引言

本文档为基于大模型（通义千问）的自动化基线检查与自愈系统提供 V1.6 版本的综合设计概览。本版本是在 V1.5 基础上进行的一次系统性重构，旨在使设计更加精简、务实和可执行。

**V1.6 版本十大核心变更**：

| 序号 | 变更项 | 变更内容 |
| :--: | :----- | :------- |
| 1 | Agent 采集精简 | 移除硬件、网络、软件/进程等所有复杂采集项，仅保留 IP 地址、主机名、系统类型三项核心身份信息。 |
| 2 | Agent 安装权限 | 明确安装脚本以 `root` 权限执行，安装路径为 `/usr/local/bin/baseline-agent`。 |
| 3 | 移除实时通讯 | 前端移除 WebSocket，改为页面加载和用户手动刷新时更新数据，简化架构复杂度。 |
| 4 | Agent 构建与分发 | Agent 不打包为 Docker 镜像，而是在容器内交叉编译后，将二进制产物上传至 MinIO 文件服务器供下载。 |
| 5 | 前端文档深化 | 提供更清晰的目录结构、数据获取策略、Pinia Store 详细设计和组件规范。 |
| 6 | PRD 同步更新 | 精简资产大盘展示字段，移除实时通讯描述，更新 Agent 安装页说明。 |
| 7 | 构建体系重构 | 每个子项目（Agent、Backend、Frontend）均提供 `Makefile` + `build.sh`，明确构建流程。 |
| 8 | docker-compose 职责分离 | `docker-compose.yml` 仅用于启动预构建好的镜像，不包含任何构建逻辑。 |
| 9 | 通讯层设计补全 | 补全了 Agent 与后端的 gRPC 通讯设计，详细描述了数据入库流程和安装脚本分发接口。 |
| 10 | AI 提示词全面重写 | 提示词覆盖全栈所有模块，每个任务均有详细的实现指导，而非仅列出标题。 |

## 2. 核心技术栈

| 组件             | 技术栈                                      |
| :--------------- | :------------------------------------------ |
| **前端展示**     | Vue 3 + Vite + TypeScript + Pinia + Element Plus |
| **后端 API**     | Go (Gin) + gRPC                             |
| **Agent 执行端** | Go (静态编译，无依赖)                       |
| **关系型数据库** | PostgreSQL 14                               |
| **高速缓存**     | Redis 7                                     |
| **对象存储**     | MinIO                                       |
| **AI 大脑**      | 通义千问 (API Key + OpenAI 兼容模式)        |
| **容器化**       | Docker + Docker Compose (仅用于启动)        |

## 3. 系统架构概览

系统分为四个核心层次：

**前端展示层**负责提供用户界面，通过 RESTful API 与后端交互，数据更新依赖用户操作触发。

**后端核心层**是系统的中枢，由 Gin HTTP 服务器和 gRPC 服务器两部分组成，分别负责与前端和 Agent 的通讯，同时编排对 LLM、数据库、Redis 和 MinIO 的调用。

**Agent 执行层**是部署在目标主机上的轻量级守护进程，通过 gRPC 双向流与后端保持长连接，负责上报身份信息、维持心跳和执行脚本。

**数据与存储层**由 PostgreSQL（持久化业务数据）、Redis（Agent 状态缓存）和 MinIO（文件存储，包括 Agent 二进制包和基线模板文件）组成。
