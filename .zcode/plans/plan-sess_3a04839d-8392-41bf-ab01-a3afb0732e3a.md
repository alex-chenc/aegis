## 修复目标

把漏洞 POC/修复脚本从“按主机生成、按主机返回脚本状态”调整为“按 CVE + script_type 生成一份通用脚本”。脚本生成和状态接口不再要求或返回主机信息；脚本执行仍保留目标主机选择，因为下发命令必须指定 host_ids。

## 设计原则

1. 生成阶段不再依赖 `host_id`、`host_ip`、`hostname`、`os_type`。
2. 同一 CVE + `poc|fix` 只有一份通用脚本和一个生成状态。
3. 执行阶段继续选择受影响主机或自定义 CVE 的全量主机，并对选中的在线主机下发同一份通用脚本。
4. 尽量复用现有路由，减少前后端联动破坏：
   - `POST /api/v1/vulnerability/:cve_id/scripts/generate` 保留路径，但 body 只需要 `script_type`。
   - `GET /api/v1/vulnerability/:cve_id/host-scripts?script_type=...` 保留路径兼容，但返回通用脚本状态，不再返回 host 列表。
   - `POST /api/v1/vulnerability/:cve_id/scripts/execute` 保持 `host_ids` 必填。

## 风险与回滚

风险主要在数据库兼容：现有表名叫 `host_vulnerability_scripts`，且可能有 `host_id NOT NULL` 与 `(cve_id, host_id, script_type)` 唯一索引。如果实际迁移成本较高，我会优先采用兼容迁移，让历史主机维度记录归并为通用脚本记录，避免破坏已有部署。

回滚方式：恢复生成接口要求 host_ids、仓储按 `cve_id + host_id + script_type` 查询、前端按主机行展示脚本状态；执行任务日志和 gRPC 下发链路不需要回滚。
