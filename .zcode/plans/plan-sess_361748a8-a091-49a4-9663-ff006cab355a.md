# 修复 Agent 日志风暴（eBPF 自我监控反馈循环）并重新部署

## 根因回顾
`file.bpf.c` 把 `/proc/` 列为敏感路径且不排除 Agent 自身 PID；`processFileEvent` 对每条文件事件调用 `GetProcessTree`（`findChildren` 扫描整个 `/proc`，对每个 pid `openat /proc/<N>/stat`）。这些 `/proc` open_read 由 Agent 自身发起 → 被 eBPF 捕获成新事件 → 再触发 `GetProcessTree` → 自维持放大循环（~120 事件/秒，3 行 INFO/事件）。`strace` 已证实 pid 230647 在紧凑循环 `openat("/proc/.../stat")`。

## 代码改动（4 个文件 + 1 个回归测试）

### A. `agent/internal/ebpf/bpf/file.bpf.c`（BPF 主修复）
1. 新增 `agent_pid_config`（`BPF_MAP_TYPE_ARRAY`，1 entry，u32 key/value）+ `is_agent_self()` 内联助手：读 map[0]，若非 0 且 `bpf_get_current_pid_tgid()>>32 == *agent_pid` 则返回 1。
2. 在每个文件 tracepoint handler 顶部加 `if (is_agent_self()) return 0;`：`trace_openat`/`trace_openat2`/`trace_creat`/`trace_unlinkat`/`trace_renameat`/`trace_renameat2`/`trace_chmod`/`trace_fchmodat`/`trace_chown`/`trace_fchownat`。在内核侧直接丢弃 Agent 自身文件操作，事件不再进入 ringbuf/perf。
3. 按你的要求把 `/proc/` 从 `is_sensitive_path()` 移除（降噪；自排除已断回路，此为额外硬化）。保留 `/etc/`、`/root/`、`/boot/`、`/usr/bin|sbin/`、`/bin/`、`/sbin/`、`/lib/systemd/`、`/etc/systemd/`、`/var/spool/cron/`、`/tmp/`、`/var/tmp/`。

### B. `agent/internal/ebpf/loader.go`（Go：注入 PID + 纵深防御 + 日志）
1. `Loader` 增加 `agentPID uint32` 字段；`NewLoaderWithOptions` 中设为 `uint32(os.Getpid())`。
2. `loadProgram`：在 `NewCollectionWithOptions` 成功后、attach 之前，对 `cfg.name == "file"` 写入 `coll.Maps["agent_pid_config"].Put(uint32(0), l.agentPID)`（沿用本包 `.Put()` 习惯，见 `agent_guard_policy.go:111`），失败仅 Warn，成功 Info 日志 `agent_file_self_pid_exclusion_configured`。
3. `processFileEvent` 顶部加纵深防御：`if e.Pid == l.agentPID { return }`（BPF map 写失败时仍兜底，且可单测）。
4. `processFileEvent` 第 528 行 `logger.Info("[eBPF] File event captured"...)` → `logger.Debug(...)`，并补 `zap.String("path", path)`（之前日志缺 path 是排查难点）。

### C. `agent/internal/ebpf/pipeline.go`（日志降级）
- 第 126 行 `[FileEvent] Processing file access event` Info → Debug。
- 第 138 行 `[FileEvent] No Sigma rules matched` Info → Debug。
（命中规则的 `Rule matched` 仍保留 Info。）

### D. 回归测试 `agent/internal/ebpf/loader_file_selfpid_test.go`（新增）
- 沿用 `guard_monitor_test.go` 的字节缓冲 + `&Loader{}` 模式：构造 564 字节 `FileEvent`，其 Pid（偏移 8）设为 `loader.agentPID`，调用 `processFileEvent(buf)`，断言 `eventChan` 仍为空（早返回、不触达 `/proc` 富化）；再用一个非自身 pid 断言事件被发送。纯单测，无需内核。

## 构建 & 测试
1. 宿主机 `cd agent && go test ./internal/ebpf/...`（含新回归测试与既有纯单测；`//go:build ebpf_runtime` 的真机测试默认跳过）。
2. 镜像内重建：`cd agent && docker build -f Dockerfile --build-arg EBPF_BASE_IMAGE=aegis-agent-builder-ubi8:5.8.0 -t aegis-agent-artifacts:local .`（重新编译 `file.bpf.c` → 新 `file.{ringbuf,perf}.bpf.o`，重编 Go 二进制，重打包 `aegis-agent.tar.gz`）。
3. 用 builder 镜像重新生成仓库内 `internal/ebpf/bpf/obj/file.{ringbuf,perf}.bpf.o`，保持提交对象与 `.bpf.c` 一致（`docker run --rm -v <agent>:/src/agent aegis-agent-builder-ubi8:5.8.0 make ... bpf`）。

## 重新部署到运行主机（systemd：`aegis-agent.service`，root，WorkingDirectory=/opt/aegis-agent）
1. 从镜像拷出 `aegis-agent.tar.gz` 到 `agent/dist/`。
2. `systemctl stop aegis-agent`。
3. 备份旧文件：`/opt/aegis-agent/aegis-agent`、`bpf/file.ringbuf.bpf.o`、`bpf/file.perf.bpf.o` → `.bak.<时间戳>`（可回滚）。
4. 解包新 `aegis-agent-linux-amd64` 与 `bpf/file.{ringbuf,perf}.bpf.o` 覆盖到 `/opt/aegis-agent/`。
5. `systemctl start aegis-agent`。
6. 验证风暴停止：
   - 日志出现 `agent_file_self_pid_exclusion_configured`；
   - `/opt/aegis-agent/logs/agent.log` 不再每秒新增 `[eBPF] File event captured`/`[FileEvent] ...` INFO 行（已降 Debug），30s 内文件大小基本稳定；
   - `strace -f -e openat -p <agent-pid>` 确认不再自维持 `/proc/<N>/stat` 风暴（仅余少量合法富化读取）；
   - Agent 仍正常心跳、gRPC 流未断。
